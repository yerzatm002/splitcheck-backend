# SplitCheck deployment

## 1. Neon PostgreSQL

1. Create a Neon project and database.
2. In Neon, open **Connect** and copy a PostgreSQL connection string.
3. Prefer the **pooled** connection string for the web application if Neon offers both pooled and direct variants.
4. Keep `sslmode=require` in the URL.
5. Put it in `.env` locally as `DATABASE_URL=...`.

The backend accepts both:

```text
postgresql://...
postgresql+psycopg://...
```

It normalizes the first form automatically for SQLAlchemy + psycopg 3.

Local Neon smoke test:

```bat
python scripts\check_db.py
```

On successful first startup, SQLAlchemy creates the MVP tables and seeds:

- `bauyrzhan`
- `sanzhar`
- `yerzat`

with the password from `INITIAL_USER_PASSWORD`.

## 2. Local production-like backend test

Create `.env`:

```env
DATABASE_URL=postgresql://...
SECRET_KEY=<long random value>
INITIAL_USER_PASSWORD=<strong initial password>
CORS_ORIGINS=http://localhost:5173
ENVIRONMENT=development
```

Generate a secret if needed:

```bat
python scripts\generate_secret.py
```

Run:

```bat
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Check:

- `http://127.0.0.1:8000/health`
- `http://127.0.0.1:8000/ready`
- `http://127.0.0.1:8000/docs`

## 3. Render

Push this backend directory to GitHub, then either create a Render Web Service manually or use `render.yaml` as a Blueprint.

The repository includes `.python-version` with Python 3.11 because the OCR stack is not intended to run on Render's newer default Python runtime.

Required Render environment variables:

```text
DATABASE_URL=<Neon connection string>
INITIAL_USER_PASSWORD=<strong initial password>
CORS_ORIGINS=https://YOUR-FRONTEND.vercel.app
ENVIRONMENT=production
```

`SECRET_KEY` can be generated by the Blueprint or entered manually.

Build command:

```text
python -m pip install --upgrade pip && pip install -r requirements.txt
```

Start command:

```text
uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

Health check path:

```text
/health
```

After deployment, verify:

```text
https://YOUR-API.onrender.com/health
https://YOUR-API.onrender.com/ready
https://YOUR-API.onrender.com/docs
```

## 4. Vercel frontend

In Vercel add:

```text
VITE_API_URL=https://YOUR-API.onrender.com/api
```

Then redeploy the frontend.

After Vercel assigns the final domain, update the Render variable:

```text
CORS_ORIGINS=https://YOUR-FRONTEND.vercel.app
```

For both the production domain and a local frontend, use a comma-separated list:

```text
CORS_ORIGINS=https://YOUR-FRONTEND.vercel.app,http://localhost:5173
```

Then redeploy/restart the Render service.

## 5. Important OCR note

PaddleOCR is lazy-loaded on the first OCR request. The first scan can therefore be much slower than subsequent scans. PaddlePaddle/OpenCV are also memory-heavy compared with a normal FastAPI API. If a very small Render instance is terminated for memory use, move OCR to a larger instance or a separate OCR worker/service; the REST API contract can remain unchanged.

## OCR performance notes

The production build now limits receipt images to about 1800 px on the longest side, reuses one PaddleOCR instance per process, disables the angle-classification pass, and runs OCR in FastAPI's thread pool. The frontend also compresses phone photos before upload.

For diagnosis, Render logs now include preprocessing, model initialization, inference, and total OCR timings.
