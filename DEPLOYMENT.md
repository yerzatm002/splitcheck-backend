# SplitCheck deployment

## Render OCR fix

The receipt OCR models are now downloaded **during the Render build**, not during a user's first scan.

Build command:

```text
python -m pip install --upgrade pip && pip install -r requirements.txt && python scripts/preload_ocr.py
```

The script downloads only the two models SplitCheck actually uses:

- PP-OCRv3 English text detector
- PP-OCRv3 Latin text recognizer

The angle-classification model is not used or downloaded.

At runtime `app/services/ocr_service.py` loads the models from:

```text
ocr_models/det
ocr_models/rec
```

`PRELOAD_OCR_ON_STARTUP=true` makes FastAPI initialize PaddleOCR when the service starts. This means the first receipt scan no longer pays the model initialization cost either.

### What you should see in Render build logs

```text
[ocr-preload] downloading det: ...
[ocr-preload] det: ready at .../ocr_models/det
[ocr-preload] downloading rec: ...
[ocr-preload] rec: ready at .../ocr_models/rec
[ocr-preload] all required OCR models are ready
```

### What you should NOT see during a scan

There should be no runtime lines such as:

```text
download https://paddleocr.bj.bcebos.com/...
```

Instead the runtime log should contain something like:

```text
PaddleOCR initialized from preloaded models in 4.21s (...)
OCR preprocessing: ...
PaddleOCR inference finished in ...s
Receipt OCR complete: ...
```

## Required Render environment variables

```text
DATABASE_URL=<Neon pooled PostgreSQL URL>
INITIAL_USER_PASSWORD=<strong initial password>
CORS_ORIGINS=https://YOUR-FRONTEND.vercel.app,http://localhost:5173
ENVIRONMENT=production
PRELOAD_OCR_ON_STARTUP=true
```

`SECRET_KEY` may be generated by the Render Blueprint or entered manually.

Start command:

```text
uvicorn app.main:app --host 0.0.0.0 --port $PORT
```

Health check:

```text
/health
```

## Local development

Because `ocr_models/` is intentionally not committed, run this once locally before OCR testing:

```bat
python scripts\preload_ocr.py
```

Then start FastAPI normally:

```bat
uvicorn app.main:app --reload
```


## OCR runtime-download guard

The Render build preloads detector, Latin recognizer, and classifier model files into `ocr_models/`. The classifier is preloaded only because PaddleOCR 2.x may resolve it during engine construction even when angle classification is disabled. Runtime OCR still calls `ocr(..., cls=False)`, so the classifier is not executed. After deployment, normal receipt requests must not contain `download https://paddleocr...` in runtime logs.
